# OPT Alpha 01 内测说明

## Alpha 01 的目的

Alpha 01 不是正式版，也不是一次“大而全”的功能展示。

这个阶段最重要的是验证：

- 新用户能不能开始；
- 能不能理解当前状态；
- 出问题时能不能恢复；
- 重启、长任务和长对话之后能不能继续；
- 哪些地方仍然要求用户理解太多内部概念。

## 推荐测试旅程

第一批测试者可以重点覆盖：

1. **第一次打开**：从解压到进入首页 / 项目准备。
2. **准备一个项目**：选择 Git 项目并走到 READY。
3. **已有环境再次启动**：确认不会无意义重复首次流程。
4. **Runner 不可用**：看提示是否能带你找到修复方向。
5. **正常长任务静默**：确认正常等待没有被误报成故障。
6. **任务异常**：当任务 stalled / unreachable 时，能否理解刷新、续接和换新对话的区别。
7. **CI 失败**：能否从失败状态进入 Repair 路径。
8. **重启继续**：关闭并重新打开 OPT，确认重要上下文仍然可继续。

如果你的屏幕设置是 125% / 150% 缩放，或者窗口较小，也欢迎重点反馈布局问题。

## 什么样的反馈最有价值

非常有价值：

- “我不知道这个状态是什么意思。”
- “我不知道下一步该点哪里。”
- “它失败了，但我不知道是我需要处理还是继续等。”
- “我不敢点，因为不知道会不会破坏我的项目。”
- “重启后我不知道原来的任务去哪了。”
- “我以为它完成了，但其实没有。”
- “这个术语我完全不需要知道。”

同样欢迎普通 Bug、崩溃、兼容问题和视觉问题。

## 问题严重程度

我们内部会按影响处理，但测试者不需要自己判断优先级。

大致上：

- **P0**：数据、安全、权限风险，或核心流程完全不可用。
- **P1**：核心流程阻塞且没有合理绕过方式。
- **P2**：有绕过方式，但明显影响理解、效率或信任。
- **P3**：低频体验、视觉、措辞问题。

## 不建议做的事

- 不要为了制造错误而破坏真实 Runner / Git 环境。
- 不要把个人 Token、密码、私有仓库完整内容发到公开 Issue。
- 不要把 Alpha 包当作正式稳定版本扩散。
- 不需要为了“测试全面”而把所有页面全部点完。

自然使用中遇到的问题更有价值。
