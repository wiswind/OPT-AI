# OPT Alpha 01 故障排查

这份文档只列最常见的第一步，不要求用户自己成为运维人员。

## OPT 打不开

先确认：

- ZIP 是否完整解压；
- `OPTAssetLite.exe` 与 `BrainLite.SharedConnector.exe` 是否仍在同一目录；
- 是否从本仓库 Releases 下载；
- Windows 是否拦截了未签名程序。

如果程序启动后立即退出，请保留大概发生时间，并查看：

```text
%LOCALAPPDATA%\OPTAssetLite\logs\app.log
```

## 项目一直不是 READY

不要连续重复点击。

先看项目准备界面指出的是哪一类问题：

- GitHub 登录
- 仓库关联
- Runner / Bridge
- Workflow 路由
- CI 失败

优先按当前显示的问题修复，再重新检查。

## Runner 显示离线

先确认机器本身仍然开机、网络可用。

然后使用 OPT 中的开发环境 / Bridge 相关入口重新检查。

不要为了“重试”反复创建新的 Runner。

如果仍离线，请提交兼容性/环境问题，并说明：

- Windows 版本；
- Runner 之前是否正常；
- 是首次配置还是突然离线；
- 最近是否更换网络、机器或项目。

## CI 失败

CI 失败不等于 OPT 本身失败。

先看失败发生在：

- 项目代码测试；
- Workflow 配置；
- Runner 环境；
- OPT 项目准备流程。

修复原因后再重新验证，不建议在状态不清楚时重复执行写操作。

## 任务很久没有输出

先看 OPT 如何描述当前状态。

如果是 **expected silence / 正常静默等待**，通常无需操作。

如果显示 suspect / stalled / unreachable，再按照界面建议刷新、续接或换新对话。

不要仅因为“几分钟没输出”就重新启动同一个写任务。

## 重启后找不到原来的状态

先不要新建重复任务。

重新打开项目 / 任务页面并刷新状态。

如果仍缺失，请记录：

- 重启前任务大概处于什么状态；
- 是否正常关闭 OPT；
- 是否更换了项目路径、Windows 用户或机器；
- 重启后看到的实际状态。

## 提交 Issue 前

建议准备：

- OPT 版本；
- Windows 版本；
- 分辨率 / 缩放；
- 复现步骤；
- 实际结果；
- 预期结果；
- 截图；
- 大概发生时间；
- 是否重启后仍能复现。

日志和截图请先检查隐私信息。

不确定该不该发 Issue 时，请先去 [Discussions](../../discussions)。
